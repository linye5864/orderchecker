# 订单三方对账系统技术文档

## 一、系统概述

### 1.1 系统定位

订单三方对账系统用于验证本地配送订单与第三方配送平台之间的扣款金额一致性，确保快小象平台、第三方配送平台、商户流水三方的账目一致。系统支持多种第三方配送平台的对账处理，包括闪送、达达、蜂鸟、顺丰同城、顺丰企业C、UU跑腿、裹小递等。

### 1.2 对账场景说明

在即时配送业务中，商户通过快小象平台调用第三方配送服务会产生配送费用。当配送订单完成或取消时，第三方平台会进行扣款操作。本系统需要验证以下三方的扣款金额是否一致：

第一方为本地配送单，记录商户下单时系统记录的预估扣款金额；第二方为第三方配送平台，实际完成配送或取消订单后产生的真实扣款金额；第三方为商户流水账单，记录商户账户实际被扣除的金额。三方金额一致则对账通过，存在差异则标记异常并记录详细信息。

### 1.3 系统架构

系统采用分层架构设计，核心模块包括数据模型层、业务逻辑层和执行入口层。数据模型层包含本地配送单、流水单和第三方平台订单三个数据源的解析类；业务逻辑层封装对账核心算法和数据比较逻辑；执行入口层提供测试框架集成和批量执行能力。

## 二、数据模型

### 2.1 本地配送单

#### 2.1.1 数据来源与格式

配送单数据存储于Excel文件中，文件名格式为`配送单*.xlsx`。该文件记录了所有通过快小象平台发起配送的订单信息，是进行对账的核心依据之一。

#### 2.1.2 关键字段说明

| 字段名            | 数据类型 | 说明                           | 示例                            |
| ----------------- | -------- | ------------------------------ | ------------------------------- |
| delivery_order_sn | string   | 配送单唯一标识，作为对账关联键 | 4501132601061125993_mi94k0e84oy |
| admin_id          | int      | 商户ID，用于关联商户流水       | 2321                            |
| 发单运力          | string   | 调用的第三方配送平台           | 闪送、达达、蜂鸟                |
| 配送状态          | string   | 订单配送状态                   | 配送完成、配送中、配送异常      |
| delivery_channel  | int      | 渠道标识，0表示有效数据        | 0                               |
| free              | float    | 扣款金额，单位元               | 15.50                           |
| platform_order_id | string   | 第三方平台生成的订单号         | 第三方平台内部订单ID            |

#### 2.1.3 数据筛选条件

在进行对账时，系统只处理符合以下全部条件的有效订单：配送状态必须为“配送完成”，表示订单已完成配送流程；delivery_channel字段必须为0，表示这是正常的渠道订单而非测试或异常数据。不满足上述条件的订单将被过滤排除。

#### 2.1.4 配送单类定义

配送单的数据封装由DeliveryOrder类负责实现，该类提供以下核心方法：

```python
class DeliveryOrder:
    def __init__(self, file_path):
        """初始化加载配送单Excel文件"""
        self.data = pd.read_excel(file_path, engine='openpyxl')
        self.platforms = self.data['发单运力'].dropna().unique()

    def get_valid_data(self):
        """获取有效数据：配送完成且渠道为0"""
        return self.data[(self.data['配送状态'] == '配送完成')
                        & (self.data['delivery_channel'] == 0)]

    def get_platform_orders(self, platform):
        """获取指定平台的有效订单"""
        valid_data = self.get_valid_data()
        return valid_data[valid_data['发单运力'] == platform]

    def get_order_number_amount(self, order_number):
        """根据订单号获取扣款金额"""
        order_data = valid_data[valid_data['delivery_order_sn'] == order_number]
        return round(order_data['free'].sum(), 2)

    def get_all_orders(self, admin_id):
        """获取指定商户的所有订单号"""
        valid_data = self.data[self.data['delivery_channel'] == 0]
        return valid_data[valid_data['admin_id"] == admin_id]["delivery_order_sn"].dropna().unique()
```

### 2.2 商户流水单

#### 2.2.1 数据来源与格式

流水单记录商户账户的资金变动情况，包括充值、扣款、奖励等业务操作。数据存储于文件名包含“流水”关键字的Excel文件中。

#### 2.2.2 关键字段说明

| 字段名            | 数据类型 | 说明                          | 示例                            |
| ----------------- | -------- | ----------------------------- | ------------------------------- |
| admin_id          | int      | 商户ID                        | 3787                            |
| delivery_order_id | string   | 关联的配送订单号              | 4501132601061125993_mi94k0e84oy |
| type              | int      | 流水类型：1扣款、2充值或奖励  | 1                               |
| method            | int      | 业务类型：1和2充值、3新客奖励 | 3                               |
| money             | float    | 金额，负数表示扣款            | -15.50                          |
| before            | float    | 账户操作前余额                | 100.00                          |
| after             | float    | 账户操作后余额                | 84.50                           |
| createtime        | datetime | 记录创建时间                  | 2024-07-01 10:30:00             |

#### 2.2.3 账户余额验证公式

商户账户的余额变化遵循以下公式，系统通过该公式验证对账一致性：

```
初始金额 + 充值金额 + 新客奖励 - 扣款金额 = 账户余额
```

当等式两边差额超过允许误差范围时，判定该商户对账异常。

#### 2.2.4 流水单类定义

```python
class TransationOrder:
    def __init__(self, file_path):
        self.data = pd.read_excel(file_path, engine='openpyxl')

    def get_unique_admin_ids(self):
        """获取所有去重的商户ID"""
        return self.data['admin_id'].unique()

    def get_total_order_amount(self, admin_id, order_number):
        """获取指定商户指定订单的扣款金额"""
        admin_data = self.get_admin_data(admin_id)
        return round(abs(admin_data[
            (admin_data['delivery_order_id'] == order_number)
            & (admin_data['type'] == 1)
        ]['money'].sum()), 2)

    def get_admin_info(self, admin_id):
        """获取商户账户结算信息"""
        initial_amount = admin_data.iloc[0]['before']
        balance = admin_data.iloc[-1]['after']
        deduction_amount = abs(admin_data[admin_data['type'] == 1]['money'].sum())
        reward_amount = admin_data[(admin_data['type'] == 2) & (admin_data['method'] == 3)]['money'].sum()
        recharge_amount = admin_data[(admin_data['type'] == 2) & (admin_data['method'].isin([1, 2]))]['money'].sum()

        # 验证账户余额一致性
        difference = abs((initial_amount + reward_amount + recharge_amount - deduction_amount) - balance)
        return {'差值': difference} if difference > 0.01 else {}
```

### 2.3 第三方平台订单

#### 2.3.1 抽象基类设计

为统一不同第三方平台的接口，设计Base3rdOrder抽象基类，所有平台订单类继承该基类：

```python
class Base3rdOrder:
    def __init__(self, file_path):
        if not os.path.isfile(file_path):
            print(f"'{file_path}'文件不存在")

    def get_total_order_amount(self):
        """获取已完成订单的扣款总金额"""
        return 0

    def get_total_penalty_amount(self):
        """获取取消订单的违约金总金额"""
        return 0

    def get_order_number_info(self, order_number):
        """根据配送单订单号获取第三方订单信息"""
        return None
```

#### 2.3.2 各平台字段差异对照表

| 平台      | 完成状态 | 取消状态              | 订单金额字段             | 违约金字段                      | 订单号查询字段                        | 平台订单号字段 |
| --------- | -------- | --------------------- | ------------------------ | ------------------------------- | ------------------------------------- | -------------- |
| 闪送      | 闪送完成 | 已取消                | 实付金额(元)             | 取消单扣款金额(元)              | 三方订单编号(末尾追加逗号匹配)        | 订单编号       |
| 达达      | 已完成   | 已取消                | 运费账户消耗             | 违约金                          | 第三方订单ID                          | 达达订单ID     |
| 蜂鸟      | 已送达   | 配送异常/商户取消订单 | 配送费总金额             | 代码硬编码为0(不使用违约金字段) | 商家订单号                            | 蜂鸟订单号     |
| 顺丰同城  | 已完成   | 已取消                | 配送费总价(单位元)       | 订单取消费(单位元)              | 商家订单号                            | 顺丰订单号     |
| 顺丰企业C | 已完成   | 已取消                | 支付金额(含元字符需去除) | 取消单扣费(含元字符需去除)      | 同城运单号(使用platform_order_id查询) | 订单号         |
| UU跑腿    | 完成     | 取消                  | 实际支付金额             | 上门费                          | 三方订单号                            | UU订单号       |
| 裹小递    | 已完成   | 已退款                | 支付金额                 | 取消订单扣款                    | 订单号(使用platform_order_id查询)     | 订单号         |

> **重要差异说明**:
>
> - 蜂鸟平台在 `get_order_number_info` 中将 `order_penalty` 硬编码为 `0`，即便在取消/异常状态下也不计入违约金扣款
> - UU跑腿的完成状态是"完成"(非"已完成")，取消状态是"取消"(非"已取消")
> - 裹小递取消状态是"已退款"(非"已取消")，违约金来自"取消订单扣款"字段(非"违约金")

#### 2.3.3 典型平台实现（闪送）

```python
class ShanSongOrder(Base3rdOrder):
    def __init__(self, file_path):
        super().__init__(file_path)
        # 读取汇总信息表和订单明细表（闪送Excel有两个sheet）
        self.summary_data = pd.read_excel(file_path, sheet_name='汇总信息')
        self.order_data = pd.read_excel(file_path, sheet_name='订单明细')
        self.total_deduction_amount = self.get_total_order_amount() + self.get_total_penalty_amount()

    def get_total_order_amount(self):
        """优先尝试从汇总信息表的 D7 列获取，否则从订单明细计算"""
        if 'D7' in self.summary_data:
            return round(float(self.summary_data['D7']), 2)
        return round(self.order_data[self.order_data['订单状态'] == '闪送完成']['实付金额(元)'].sum(), 2)

    def get_total_penalty_amount(self):
        """优先尝试从汇总信息表的 D5 列获取，否则从订单明细计算"""
        if 'D5' in self.summary_data:
            return round(float(self.summary_data['D5']), 2)
        return round(self.order_data[self.order_data['订单状态'] == '已取消']['取消单扣款金额(元)'].sum(), 2)

    def get_order_number_info(self, order_number):
        """根据配送单订单号查询第三方订单信息"""
        # NOTE: 闪送的三方订单编号字段会在末尾多一个逗号，查询时需要追加
        data = self.order_data[self.order_data['三方订单编号'] == order_number + ',']

        if data is not None and not data.empty:
            orider_status = data.iloc[0]['订单状态']
            order_amount = float(str(data.iloc[0]['实付金额(元)']).replace(',', '').strip())
            order_penalty = float(str(data.iloc[0]['取消单扣款金额(元)']).replace(',', '').strip())

            # 根据订单状态决定实际扣款金额：闪送完成取实付，否则取违约金
            actual_deduction = order_amount if orider_status == '闪送完成' else order_penalty

            return {
                'actual_deduction': actual_deduction,
                'order_id': data.iloc[0]['订单编号'],
                'orider_status': orider_status,  # NOTE: 代码中实际键名为 orider_status
                'order_amount': order_amount,
                'order_penalty': order_penalty
            }
        return None
```

#### 2.3.4 特殊数据预处理

部分第三方平台的 Excel 文件在首行存在合并单元格等格式问题，需要在加载数据前进行预处理：

**顺丰同城**：检查 A1 单元格是否为"顺丰订单号"，如果不是则认为首行为多余的合并表头，删除首行并清理合并单元格后重新保存文件：

```python
def check_and_delete_first_row_if_needed(self, file_path):
    workbook = load_workbook(file_path)
    sheet = workbook.active
    a1_value = sheet['A1'].value
    if a1_value != "顺丰订单号":
        sheet.delete_rows(1)
        merged_cell_ranges = list(sheet.merged_cells.ranges)
        for merged_cell in merged_cell_ranges:
            if merged_cell.min_row == 1:
                sheet.merged_cells.remove(merged_cell)
        workbook.save(file_path)
    workbook.close()
```

**顺丰企业C**：检查首行是否全为 NaN（合并单元格导致），如果是则删除首行后重新保存：

## 三、对账核心算法

### 3.1 主流程设计

对账核心逻辑封装在DataChecker类的do_platform_check方法中，该方法接收配送单、流水单、第三方订单和平台名称四个参数，返回布尔值表示对账是否完全通过。整体流程分为五个主要步骤：数据加载与筛选、订单遍历与三方比对、金额汇总统计、结果判定与输出。

```python
def do_platform_check(self, delivery_order_file, transation_order_file, third_order, platform):
    # Step 1: 加载数据
    delivery_order = DeliveryOrder(delivery_order_file)
    transation_order = TransationOrder(transation_order_file)
    platform_data = delivery_order.get_platform_orders(platform)

    # Step 2: 初始化统计变量
    total_count = len(platform_data)
    total_pass_count = 0
    total_fail_count = 0
    total_delivery_amount = 0
    total_third_amount = 0
    total_transation_amount = 0

    # Step 3: 遍历每个订单进行三方比对
    for index, row in platform_data.iterrows():
        order_number = row['delivery_order_sn']
        admin_id = row['admin_id']
        delivery_amount = round(row['free'], 2)

        # 获取第三方订单信息
        third_order_info = third_order.get_order_number_info(order_number)

        # 获取流水单扣款金额
        transation_amount = transation_order.get_total_order_amount(admin_id, order_number)

        # 三方金额比对
        if delivery_amount == third_order_info['actual_deduction'] == transation_amount:
            total_pass_count += 1
        else:
            total_fail_count += 1
            # 记录异常详情

        # 累计金额
        total_delivery_amount += delivery_amount
        total_third_amount += third_order_info['actual_deduction']
        total_transation_amount += transation_amount

    # Step 4: 结果判定
    result = (total_delivery_amount == total_third_amount == total_transation_amount)

    # Step 5: 输出报告
    print(f"对账成功率: {total_pass_count/total_count*100}%")
    return result
```

### 3.2 异常判断逻辑

对账过程中可能出现的异常情况分为四类，每类异常有明确的判断规则和输出信息。

第一类异常是配送单订单在第三方平台订单表中找不到对应记录。这种情况表明该订单可能未被成功推送到第三方平台，或者订单号匹配字段存在差异。系统会输出“配送单订单在某平台订单中未找到”的错误信息，并记录该订单进入异常明细。

第二类异常是配送单扣款金额与第三方平台扣款金额不一致。这种情况可能由费率调整、优惠券应用或平台计费规则差异导致。系统会计算差额并判断是多扣还是少扣，输出格式为“快小象平台少扣X元”或“快小象平台多扣X元”。

第三类异常是配送单扣款金额与商户流水扣款金额不一致。这种情况表明商户账户实际扣款与系统记录不匹配，可能存在账务处理延迟或异常。系统会输出“商户流水少扣X元”或“商户流水多扣X元”的提示。

第四类异常是三方金额均不一致。这种情况最为复杂，需要同时排查平台计费和商户账务处理两个环节。系统会输出“所有平台金额不匹配”的综合错误。

```python
# 详细的异常判断实现
if delivery_amount != third_amount:
    diff = round(delivery_amount - third_amount, 2)
    if diff > 0:
        error_msg = f"快小象平台少扣'{abs(diff)}'元"
    else:
        error_msg = f"快小象平台多扣'{abs(diff)}'元"
elif delivery_amount != transation_amount:
    diff = round(delivery_amount - transation_amount, 2)
    if diff > 0:
        error_msg = f"商户流水少扣'{abs(diff)}'元"
    else:
        error_msg = f"商户流水多扣'{abs(diff)}'元"
else:
    error_msg = "所有平台金额不匹配"
```

### 3.3 金额汇总与验证

除了逐单比对，系统还会进行金额层面的汇总验证。汇总验证的逻辑是：配送单所有有效订单的扣款金额总和、第三方平台所有对应订单的扣款金额总和、商户流水单所有对应订单的扣款金额总和，这三个总和必须完全相等。如果单笔比对通过但汇总金额不一致，说明存在边界情况或数据遗漏。

```python
# 金额汇总验证
total_delivery_amount = round(platform_data['free'].sum(), 2)
total_third_amount = round(sum(third_amounts), 2)
total_transation_amount = round(sum(transation_amounts), 2)

if total_delivery_amount == total_third_amount == total_transation_amount:
    print(f"对账正常：三方扣款金额均为{total_delivery_amount}元")
else:
    print(f"对账异常：配送单{total_delivery_amount}，第三方{total_third_amount}，流水{total_transation_amount}")
```

### 3.4 特殊平台处理

部分第三方平台使用platform_order_id（第三方平台订单号）而非delivery_order_sn（配送单订单号）进行关联查询。例如顺丰企业C和裹小递平台就需要特殊处理：

```python
# 订单号查询策略
if platform in ('裹小递', '顺丰企业C'):
    # 使用平台订单ID查询
    platform_id = row['platform_order_id']
    third_order_info = third_order.get_order_number_info(platform_id)
else:
    # 使用配送单订单号查询
    third_order_info = third_order.get_order_number_info(order_number)
```

## 五、错误处理与容错

### 5.1 浮点数精度处理

系统在两个不同场景下使用了不同的精度比较策略：

**场景一：商户流水对账（`check_admin_info`）**使用 `math.isclose` 容差判断，验证商户账户余额公式是否成立：

```python
import math

total_order_amount = round(total_order_amount, 2)
if math.isclose(total_order_amount, total_amount):
    result = True
```

**场景二：第三方平台对账（`do_platform_check`）**使用严格等于（`==`）进行逐单金额对比和总额对比：

```python
# 逐单比对：三方金额必须严格相等
if delivery_order_amount == third_order_actual_deduction == transation_order_amount:
    total_pass_count += 1

# 总额比对：同样使用严格等于
if total_amount == total_third_amount == total_transation_amount:
    result = True
```

> **NOTE**: 所有金额在累加和比较前均使用 `round(x, 2)` 保留两位小数来减少浮点误差，而非使用容差范围。仅在商户余额验证中使用了 `math.isclose`。

### 5.2 数据文件校验

系统在各数据源加载时进行基础校验：检查文件是否存在、检查文件是否可读。如果校验失败，系统打印错误信息（通过 `print` 而非异常抛出），但不会立即终止整个对账流程——每个平台的对账是独立的测试用例。

### 5.3 异常订单记录

对于对账失败的订单，系统记录两层信息：`details` 列表记录每单的完整对账过程（含 Pass/Fail 标记），`exception_msg` 列表单独记录失败订单的差额信息。最终输出中，如果整体对账失败会额外输出 `exception_msg` 中的失败明细。

## 六、扩展指南

### 6.1 新增第三方平台支持

要添加新的第三方配送平台支持，需要完成以下步骤：

第一步是创建订单解析类。在`_3rd_order`目录下新建`xxx_order.py`文件，继承`Base3rdOrder`类，实现三个核心方法：`__init__`方法加载数据文件、`get_order_number_info`方法实现订单查询、`get_total_order_amount`和`get_total_penalty_amount`方法实现金额汇总。

第二步是在data_checker.py中导入新类。在文件头部添加import语句，并在DataChecker类中添加对应的检查方法。

第三步是在main函数中添加测试用例。使用`add_test`函数将新的平台对账加入测试套件。

### 6.2 数据源格式变更

如果Excel文件的数据格式发生变化（如列名更改），需要修改对应解析类的字段映射。所有平台特定的字段名都集中在各平台的订单类中，便于集中维护和修改。
